# Источники примера

## Стандарт

- RFC 9110 «HTTP Semantics», IETF, июнь 2022, STD 97. Редакторы R. Fielding, M. Nottingham, J. Reschke. Текст: https://www.rfc-editor.org/rfc/rfc9110.txt, раздел 15 «Status Codes».
- Из раздела 15 взяты: правило «первая цифра — класс, две последние классификации не несут», пять классов, правило x00 для неизвестных кодов (пример 471 → 400), недействительность кодов вне 100–599 (такой ответ клиенту следует считать 5xx).
- Из 15.1: фразы вроде «Not Found» — только рекомендации, их можно заменить или опустить; эвристически кэшируются 200, 203, 204, 206, 300, 301, 308, 404, 405, 410, 414, 501.
- RFC 2324 «Hyper Text Coffee Pot Control Protocol (HTCPCP/1.0)», L. Masinter, 1 апреля 1998: https://www.rfc-editor.org/rfc/rfc2324.txt, раздел 2.3.2 «418 I'm a teapot»: «Any attempt to brew coffee with a teapot should result in the error code "418 I'm a teapot". The resulting entity body MAY be short and stout.»

### Что RFC 9110 говорит о 418 (§ 15.5.19), дословно

> [RFC2324] was an April 1 RFC that lampooned the various ways HTTP was abused; one such abuse was the definition of an application-specific 418 status code, which has been deployed as a joke often enough for the code to be unusable for any future use. Therefore, the 418 status code is reserved in the IANA HTTP Status Code Registry. This indicates that the status code cannot be assigned to other applications currently. If future circumstances require its use (e.g., exhaustion of 4NN status codes), it can be re-assigned to another use.

### Все 46 кодов RFC 9110

Английская фраза — из заголовка подраздела RFC 9110, смысл по-русски — пересказ первого абзаца того же подраздела (для 301 и 308 ещё и примечаний). Цитата на странице — первое предложение абзаца дословно, для 418 — оба абзаца.

| 100 | Continue | Informational | § 15.2.1 | продолжай | Начало запроса получено, и сервер его пока не отклонил. Окончательный ответ он пришлёт, когда получит запрос целиком и выполнит его. |
| 101 | Switching Protocols | Informational | § 15.2.2 | смена протокола | Сервер понял просьбу клиента сменить протокол на этом соединении (поле Upgrade) и согласен. В ответе он обязан прислать Upgrade с протоколом, который будет действовать дальше. |
| 200 | OK | Successful | § 15.3.1 | всё в порядке | Запрос выполнен. Что лежит в ответе, зависит от метода запроса. |
| 201 | Created | Successful | § 15.3.2 | создано | Запрос выполнен, и в результате появился один или несколько новых ресурсов. Главный из них указан в поле Location, а если его нет, это сам целевой URI. |
| 202 | Accepted | Successful | § 15.3.3 | принято | Запрос принят в обработку, но она не закончена. Его могут так и не выполнить, а прислать код позже, по итогам асинхронной операции, HTTP не умеет. |
| 203 | Non-Authoritative Information | Successful | § 15.3.4 | информация не из первоисточника | Запрос выполнен, но по дороге содержимое изменил преобразующий прокси: оно отличается от ответа 200 исходного сервера. |
| 204 | No Content | Successful | § 15.3.5 | нет содержимого | Сервер выполнил запрос, и прислать в содержимом ответа ему больше нечего. |
| 205 | Reset Content | Successful | § 15.3.6 | сбрось содержимое | Сервер выполнил запрос и просит клиента вернуть «вид документа», из которого ушёл запрос, в исходное состояние. |
| 206 | Partial Content | Successful | § 15.3.7 | частичное содержимое | Сервер выполняет запрос диапазона: передаёт одну или несколько частей выбранного представления. |
| 300 | Multiple Choices | Redirection | § 15.4.1 | несколько вариантов | У ресурса несколько представлений, у каждого свой адрес. Сервер даёт список, чтобы клиент выбрал нужное. |
| 301 | Moved Permanently | Redirection | § 15.4.2 | перемещено навсегда | Ресурсу назначен новый постоянный URI, и все будущие ссылки должны вести туда. По историческим причинам клиент может сменить POST на GET; если это нежелательно, есть 308. |
| 302 | Found | Redirection | § 15.4.3 | найдено | Ресурс временно лежит по другому URI. Перенаправление может меняться, поэтому дальше клиенту стоит обращаться по прежнему адресу. |
| 303 | See Other | Redirection | § 15.4.4 | смотри другое | Сервер отсылает клиента к другому ресурсу из поля Location: это косвенный ответ на исходный запрос. |
| 304 | Not Modified | Redirection | § 15.4.5 | не изменилось | Условный GET или HEAD дал бы 200, но условие оказалось ложным. У клиента уже есть действующая копия, пусть ею и пользуется. |
| 305 | Use Proxy | Redirection | § 15.4.6 | используй прокси | Код был в прошлой версии спецификации и теперь устарел. |
| 306 | (Unused) | Redirection | § 15.4.7 | не используется | Код был в прошлой версии спецификации, больше не применяется и зарезервирован. |
| 307 | Temporary Redirect | Redirection | § 15.4.8 | временное перенаправление | Ресурс временно лежит по другому URI. Переходя туда автоматически, клиент не должен менять метод запроса. |
| 308 | Permanent Redirect | Redirection | § 15.4.9 | постоянное перенаправление | Ресурсу назначен новый постоянный URI, и все будущие ссылки должны вести туда. Код моложе соседей, он появился в июне 2014 года и понятен не везде. |
| 400 | Bad Request | Client Error | § 15.5.1 | неверный запрос | Сервер не может или не станет обрабатывать запрос из-за того, что считает ошибкой клиента: неверный синтаксис, сломанное кадрирование сообщения, обманная маршрутизация. |
| 401 | Unauthorized | Client Error | § 15.5.2 | нет авторизации | Запрос не выполнен: у него нет действующих учётных данных для этого ресурса. Сервер обязан прислать поле WWW-Authenticate хотя бы с одним вызовом. |
| 402 | Payment Required | Client Error | § 15.5.3 | нужна оплата | Код зарезервирован на будущее. |
| 403 | Forbidden | Client Error | § 15.5.4 | запрещено | Сервер понял запрос, но отказывается его выполнять. Если хочет объяснить почему, пишет причину в содержимом ответа. |
| 404 | Not Found | Client Error | § 15.5.5 | не найдено | Исходный сервер не нашёл текущего представления ресурса или не хочет признавать, что оно есть. Временно это или навсегда, код не говорит. |
| 405 | Method Not Allowed | Client Error | § 15.5.6 | метод не разрешён | Метод из строки запроса серверу известен, но этот ресурс его не поддерживает. Сервер обязан прислать поле Allow со списком того, что поддерживается. |
| 406 | Not Acceptable | Client Error | § 15.5.7 | неприемлемо | У ресурса нет представления, которое устроило бы клиента по полям проактивного согласования, а отдавать вариант по умолчанию сервер не хочет. |
| 407 | Proxy Authentication Required | Client Error | § 15.5.8 | нужна аутентификация на прокси | Как 401, только аутентифицироваться клиенту нужно на прокси. Прокси обязан прислать поле Proxy-Authenticate. |
| 408 | Request Timeout | Client Error | § 15.5.9 | время запроса вышло | Сервер не получил полного сообщения запроса за то время, которое был готов ждать. |
| 409 | Conflict | Client Error | § 15.5.10 | конфликт | Запрос не выполнен из-за конфликта с текущим состоянием ресурса. Код для случаев, когда пользователь может разрешить конфликт и отправить запрос снова. |
| 410 | Gone | Client Error | § 15.5.11 | удалено | Ресурса на исходном сервере больше нет, и, скорее всего, навсегда. Если сервер не знает, навсегда ли, ему следует ответить 404. |
| 411 | Length Required | Client Error | § 15.5.12 | нужна длина | Сервер не примет запрос без Content-Length. Клиент может повторить его, добавив корректное поле. |
| 412 | Precondition Failed | Client Error | § 15.5.13 | предусловие не выполнено | Одно или несколько условий из полей заголовка запроса оказались на сервере ложными. |
| 413 | Content Too Large | Client Error | § 15.5.14 | содержимое слишком велико | Сервер отказывается обрабатывать запрос: содержимое больше, чем он хочет или может обработать. |
| 414 | URI Too Long | Client Error | § 15.5.15 | URI слишком длинный | Целевой URI длиннее, чем сервер готов разбирать. Редкий случай: например, клиент ушёл в бесконечную петлю перенаправлений. |
| 415 | Unsupported Media Type | Client Error | § 15.5.16 | неподдерживаемый тип содержимого | Содержимое запроса в формате, который этот метод на этом ресурсе не поддерживает. |
| 416 | Range Not Satisfiable | Client Error | § 15.5.17 | диапазон недостижим | Диапазоны из поля Range отклонены: ни один не выполним, или клиент запросил слишком много мелких либо пересекающихся диапазонов. |
| 417 | Expectation Failed | Client Error | § 15.5.18 | ожидание не оправдалось | Ожидание из поля Expect не смог выполнить хотя бы один из серверов по пути. |
| 418 | (Unused) | Client Error | § 15.5.19 | не используется | RFC 2324 был первоапрельским и высмеивал, как злоупотребляют HTTP. Одной из шуток был код 418, и его так часто ставили ради шутки, что ни для чего другого он теперь не годится. Поэтому 418 зарезервирован в реестре кодов IANA: другим приложениям его не отдают, но если коды 4NN когда-нибудь кончатся, его могут переназначить. |
| 421 | Misdirected Request | Client Error | § 15.5.20 | запрос не по адресу | Запрос попал на сервер, который не может или не хочет дать авторитетный ответ для этого URI. |
| 422 | Unprocessable Content | Client Error | § 15.5.21 | необрабатываемое содержимое | Тип содержимого серверу понятен и синтаксис верен, но выполнить инструкции внутри он не смог. |
| 426 | Upgrade Required | Client Error | § 15.5.22 | нужно обновление | Сервер отказывается выполнять запрос по текущему протоколу, но может согласиться, если клиент перейдёт на другой. Он обязан прислать поле Upgrade. |
| 500 | Internal Server Error | Server Error | § 15.6.1 | внутренняя ошибка сервера | Сервер столкнулся с непредвиденным условием и не смог выполнить запрос. |
| 501 | Not Implemented | Server Error | § 15.6.2 | не реализовано | Сервер не поддерживает функцию, нужную для запроса. Это правильный ответ, когда сервер не знает метод запроса. |
| 502 | Bad Gateway | Server Error | § 15.6.3 | плохой шлюз | Сервер, работая шлюзом или прокси, получил недопустимый ответ от сервера, к которому обращался. |
| 503 | Service Unavailable | Server Error | § 15.6.4 | сервис недоступен | Сервер сейчас не может обработать запрос: временная перегрузка или плановое обслуживание. Обычно это проходит, и сервер может прислать Retry-After. |
| 504 | Gateway Timeout | Server Error | § 15.6.5 | шлюз не дождался | Сервер, работая шлюзом или прокси, не дождался вовремя ответа от вышестоящего сервера. |
| 505 | HTTP Version Not Supported | Server Error | § 15.6.6 | версия HTTP не поддерживается | Сервер не поддерживает или отказывается поддерживать мажорную версию HTTP из запроса. |
